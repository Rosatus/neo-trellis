# Neo-Trellis 0.4.0 · 多功能项目规划与连续交付

从这个版本起，可以把一个项目目标拆成多份能独立验收的 PRD。用户可以先确认近期功能，也可以提前审阅整组 PRD，一次授权 agent 按依赖开发到成品验收通过。已有项目通过一次 `init` 刷新获得新能力。

## 用户能做什么

| 用户意图 | 0.4.0 的行为 |
| --- | --- |
| “把这个目标拆开，先细化前两项” | `neo-trellis-plan` 默认渐进规划。列出切片、直接依赖、验收示例和推荐顺序，只展开选中项。新项目可以先交付一条真实可运行的骨架路径。 |
| “完整规划，整组确认后开发到成品” | 先澄清共享契约，再展示每项 PRD 正文，支持分批审阅和整组确认。实施授权可覆盖指定条目或整组。产品级场景通过后，计划才算完成。 |
| “查看这个计划的进度”或“继续第二项” | 按稳定 ID 读取目标计划，核对当前 PRD 和直接依赖的交付证据。即使上次在 PRD 归档后、计划回写前中断，也可以恢复进度。 |

## 已有项目从 0.3.1 升级

要求 Node.js 20 或更高版本。进入目标项目根目录，按实际宿主选择 `--codex`、`--claude` 或 `--pi`，可以组合使用。下面以已安装 Codex 的项目为例；安装器也会刷新项目清单中已登记的其他宿主。

```sh
npx --yes neo-trellis@0.4.0 --version
npx --yes neo-trellis@0.4.0 init --codex --dry-run
npx --yes neo-trellis@0.4.0 init --codex
npx --yes neo-trellis@0.4.0 doctor
```

1. 第一条应输出 `0.4.0`。预览应列出新规划 skill、已有知识和 PRD skill、项目路由及清单等需要刷新的文件。只更新全局 CLI 的项目仍需执行 `init`。
2. 旧项目的独立 PRD 可照常继续和归档，无需批量补计划或重写旧文档。项目知识、计划及 PRD 均属于用户。遇到 `Locally modified integration` 时，先核对并保留或合并对应文件中的本地定制，再重试；安装备份位于 `.neo-trellis-backups/`。
3. 完成后再次运行相同的 `init --codex --dry-run`，预期为零项写入。重新打开宿主，检查 `neo-trellis-plan` 是否可发现，试问“列出这个项目的计划”。新升级且尚未创建计划的项目，列表应为空。`doctor` 只能检查静态安装状态。

## 后续 agent 的维护入口

- **计划与 PRD 的归属。** 计划保存在 `.neo-trellis/plans/<plan-id>/plan.md`，记录产品目标、授权范围、依赖与整体验收。单项验收证据保存在 `.neo-trellis/prds/{active,archive}/<prd-id>/prd.md`。计划引用稳定 PRD ID，PRD 记录父计划 ID 和条目 ID。读取归档正文的状态与证据，可区分已交付、已取消和已被取代的条目。
- **修改源文件并刷新安装副本。** 规划规则在 `src/plan.mjs`，知识路由在 `src/knowledge.mjs`，PRD 衔接在 `src/prd.mjs`，三宿主分发在 `src/platforms.mjs`。修改后从仓库根目录运行 `node bin/neo-trellis.mjs init --codex --claude --pi`，把生成的宿主 skill、内部回退文档和 manifest 随改动一起检查。[规划实现](https://github.com/Rosatus/neo-trellis/blob/v0.4.0/src/plan.mjs) · [安装与升级测试](https://github.com/Rosatus/neo-trellis/blob/v0.4.0/test/install.test.mjs)
- **保留两个独立决定。** 规划深度决定要提前澄清多少 PRD，执行授权决定开发到哪里。查询进度、确认文档和授权实施各有独立含义。新会话由用户指定继续哪个计划；宿主关闭后的重新启动仍由宿主负责。

## 验证范围

本地 Node.js 24 的 `npm run check` 通过 93 项测试，包含三宿主分发、旧指纹升级、用户文档保留和重复初始化。Codex 实际列出了新 skill；Claude Code 和 Pi 验证了安装文件与格式。两功能 CLI 演练覆盖归档后回写中断，以及各 PRD 分别通过但成品联测失败的情况；修复后从空目录重新验证成功。恢复演练使用独立命令进程。[逐项验收记录](https://github.com/Rosatus/neo-trellis/blob/v0.4.0/.neo-trellis/prds/archive/project-planning/prd.md) · [与 0.3.1 比较](https://github.com/Rosatus/neo-trellis/compare/v0.3.1...v0.4.0)
