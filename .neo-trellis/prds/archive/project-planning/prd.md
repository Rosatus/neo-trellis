# 大目标拆分与计划追踪

2026-11-18，用户提出完整拆分和一次授权开发成品的需求，在评估规划深度与执行授权独立、提前跑通端到端切片的方案后，确认实施：“按照你认为的最优实践进行开发”。

## 目标与范围

为使用 Codex、Claude Code、Pi 的项目提供 `neo-trellis-plan`。用户可以渐进澄清单项，也可以提前审阅整组可执行 PRD。计划负责成品目标、顺序、共享契约和整体验收，PRD 负责单项契约与交付证据。按指定计划从项目文件接手，控制每轮开发载入的上下文。

采用现有 Markdown skill 分发、项目入口与安装保护。暂缓新增用户 CLI、后台调度、自动启动宿主和并行执行。

## 已确认的行为与验收

1. AC-1 大目标按独立结果拆分，记录验收示例、直接依赖、顺序和成品场景。已有项目复用现行模块契约，零起步骨架跑通首条真实路径。单个明确功能可直接走 PRD。
2. AC-2 渐进模式只展开选中项，完整模式在实施前展示并确认全部 PRD 和共享约定，允许分批审阅、整组确认。校验稳定 ID、依赖闭合且无环，提前验证影响后续边界的未知。
3. AC-3 区分明确授权的只规划、指定切片和整组实施。连续实施只选已确认、在授权内且依赖已交付的条目。可以在同一次授权下完成两个有依赖的功能。
4. AC-4 知识与 PRD 入口能按需列出、读取和更新计划，保持双向引用。按 ID 恢复和修正中断回写，区分完成、取消、被取代。单项归档后能继续下一项，独立 PRD 保留原有生命周期。
5. AC-5 成品由真实入口的跨功能场景验收。单项均通过而集成失败时保留失败证据，修复并重验后才能完成计划。滚动修订不静默扩大已确认范围和授权。
6. AC-6 三宿主安装并可发现同源 skill，重复初始化和升级保留用户计划与 PRD。分别记录实际运行、模拟场景与宿主验证的范围。
